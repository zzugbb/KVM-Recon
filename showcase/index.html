项目定位与设计取舍

解决什么问题

现场通常不能调用公网分析服务，离场后又难以复现登录与 Viewer 会话。先把浏览器观察到的证据带出来，让后续研究有据可查。

为什么先留原始事实

未知厂商和动态路径也需要被记录。保留原始工件与稳定引用，再派生候选链、导航和缺口；不先猜协议，再筛选证据。

交付给谁，交付什么

现场人员手动导出 Capture Pack 2.0，工程师或获授权的 AI 离线复核。成果是证据包与研究入口，Adapter 开发由下游完成。

从浏览器事实，到可交接的证据。

查看数据契约 ↗
01

HTTP 与 HAR

请求与响应、重定向、头、已取得正文和时序；HAR 是互操作副本，原始索引与正文单独保存。

02

脚本与运行时

网络与动态脚本、Worker、WASM 及可观察 WebCrypto 调用。源码不可读取或落盘失败时记录缺口。

03

浏览器状态与画面

Cookie、Storage、IndexedDB、CacheStorage、DOM、截图、动作时间线，以及 popup / iframe / Target 血缘。

04

实时通道

WebSocket 握手与双向帧；可观察的 SSE、WebRTC DataChannel 与下载。WebTransport 当前只记生命周期，并报告 payload 缺口。

05

原始日志与补充事实

CDP 事件与命令、Chromium NetLog、console、浏览器环境；TLS / Redfish 探测提供可选补充事实，失败不阻断采集。

06

证据导航与 Replay

候选请求链、资源关系、已观察值传播和缺失证据。Replay 提供动态值与通道计划，不自动生成 Adapter。

07

完整度与自校验

工作流状态与十项门禁独立派生。COMPLETE 要求到达 KVM；正式 ZIP 还要通过引用、字节数、SHA-256 和 Schema 校验。

08

磁盘、恢复与导出

单作业、磁盘安全余量、内容寻址去重、流式 ZIP64。崩溃资料留存；完整与未完整包都由用户手动导出。

界面、采集与导出，各有职责。

证据完整，不等于适配完成。
完整度的含义
COMPLETE 评价定义范围内的浏览器可观察证据，不代表协议已识别、视频已解码或任何设备均能成功适配。未知架构不会因没有厂商签名被判缺口。
当前验证基线 ↗
原始资料 · 未脱敏
实际采集包可能含有效口令、Cookie、Token、内网地址与通道载荷。仅在受控环境中保存和交接，不上传公开 Issue。采集窗口放宽部分浏览器安全限制，只连接可信 BMC。
清晰的项目范围
不自动登录、不做 MITM、不在机房调用公网 AI、不写 Adapter、不完整解码视频。网站无需账号和后端，不接收地址、凭据或采集包。
